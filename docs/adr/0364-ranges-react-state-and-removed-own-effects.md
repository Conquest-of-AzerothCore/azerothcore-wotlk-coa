# 0364. Value ranges, minion react state and a rank's removed own effect

- Status: accepted
- Date: 2026-11-13

## Context

The B2 side a review asked for a behaviour route to Harvest Plague's "siphoning ${$m1+0+$SP*0.15} health", a read that
Undead: Protect changes for "assume a defensive behavior", and a corrected Runic Harvest value scenario.
- A rolled tick is one sample of a range: `metric_delta` judged an exact value or a lower bound only, and its player
  fixture had no spell power.
- Protect leaves the minion REACT_DEFENSIVE, as no stance does; Undead: Assault makes it REACT_AGGRESSIVE
  (AscensionNecromancerSummons.cpp:760-766). The harness did not read a minion's react state.
- The Runic Harvest value scenario read its unreadable `$t2` on effect 0, which AscensionNecromancerContracts.cpp:317-322
  removes, and stopped with "Spell effect does not exist".

## Considered options

1. A mean judge over many ticks. Rejected for now: the hit model refuses a rolled periodic amount (hits.py:385).
2. A range per tick (`after_at_least` with `after_at_most`), at no spell power and at a spell power fixture. Chosen.
3. For Protect, threat in combat or an attacker of the caster. Rejected: both read the same with and without Protect.
   A read of the minion's react state after Assault, then Protect. Chosen.
4. For Runic Harvest, `disabled_foreign_effects` on the rank's own effect. Rejected: Templar lists own effects there for
   other reasons, and its scenarios would change. A class-file `removed_own_effects` list. Chosen.

## Decision

- `metric_delta` takes `after_at_most` (with `after_at_least` at or below it): the after read must lie in the range;
  and `player_spell_power`, the player fixture's spell power.
- The harness metric `owned_creature_react_state` reads a live owned creature's `GetReactState()` (read only);
  `coverage.py` lists it as state evidence promised by "aggressive", "defensive" or "passive".
- A class file's `removed_own_effects` (`spell`, `effect`, `reason`) names effects a class contract removes from a rank;
  the value scenario does not take them as the rank's first effect.
- Without the new fields every existing scenario is generated byte-identical (`generate --class 19` and `--stack`).

## Consequences

- One tick inside the stated range is a deterministic pass for a correct server: no draw of the die leaves it.
- A spell power fixture is a precondition, named in the verdict.
