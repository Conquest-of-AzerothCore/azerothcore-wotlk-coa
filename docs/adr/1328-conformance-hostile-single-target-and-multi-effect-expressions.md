# ADR 1328: Hostile `single_target` scenarios and multi-effect `${...}` expressions

Date: 2026-11-27
Status: Accepted

## Context

Catching up Templar's server-granted `extra_spells` (class 19, per ADR 1327) surfaced two
bounded conformance-tool gaps:

1. `ExpressionParser` in `apps/coa-gameplay-test/conformance/tooltip.py` latched
   `self.effect_index` to the first own-effect reference encountered inside a `${...}`
   expression. For *Divine Stand* (`807729`), whose tooltip writes
   `increasing your threat generated by $s3% and an additional ${$m1-$m3}% from Holy spells and abilities`,
   `${$m1-$m3}` evaluates to `45%` (`215 - 170`) while `Effect[0]`'s own server value is `215%`.
   Binding the cross-effect difference to `effect_index = 0` caused `values.py` to generate
   false-alerting `effect_value e0` and `aura_amount e0` expectations against `45%`.
2. `SingleTargetSpec` / `single_target_scenario` in
   `apps/coa-gameplay-test/conformance/behaviours.py` only spawned two grouped player allies
   (`ally`, `ally2`). Hostile single-target crowd control such as *Shackle The Unrepentant*
   (`560963`, "Only 1 target can be shackled at a time.", `SPELL_ATTR5_LIMIT_N`,
   `TargetCreatureType = 36` Undead/Demon) requires two hostile creature targets of a chosen
   `creature_template` entry and optional explicit cast power.

## Decision

1. Update `ExpressionParser` in `apps/coa-gameplay-test/conformance/tooltip.py` to collect
   all distinct non-`None` own-effect indices from non-`ppl` value references (`$mN`/`$MN`)
   inside `${...}` in a set and return `None` when two or more distinct own effects are
   combined (such as `${$m1-$m3}`), while preserving single-effect expressions (including
   `${$m2+$ppl1}` per-level scaling expressions and single-effect `$sN` tokens).
2. Extend `SingleTargetSpec`, `single_target_spec`, and `single_target_scenario` in
   `apps/coa-gameplay-test/conformance/behaviours.py` with two opt-in fields defaulting to
   `None`:
   - `target_entry: int | None = None` — when set, spawns two hostile creature fixtures
     (`dummy`, `dummy2`) of that `creature_template` entry at 5 yd instead of two grouped
     player allies, casts the spell on `dummy` (reading `aura` = 1), waits out the global
     cooldown, and casts on `dummy2` (reading `aura` = 0 on `dummy` and `aura` = 1 on
     `dummy2`).
   - `cast_power: int | None = None` — when set, sets the caster's power for the spell's
     `PowerType` to `cast_power` before each cast instead of relying solely on `pay_power_steps`.
   When `target_entry` and `cast_power` are omitted (`None`), the generated ally scenario is
   byte-for-byte unchanged.
3. Extend `ChaseHaltSpec` / `chase_halt_scenario` in
   `apps/coa-gameplay-test/conformance/kinds/chase_halt.py` with opt-in `target_entry`,
   `cast_power`, optional `raises` (defaulting to empty), and `expected_ratio >= 0` (allowing
   `0` for complete stun halts on creature-type-restricted crowd control). Existing
   `chase_halt` scenarios (Necromancer `504316`) remain byte-for-byte unchanged.

## Consequences

- Multi-effect `${...}` differences no longer emit bogus single-effect `effect_value` /
  `aura_amount` checks, while single-effect tokens (`$s3%` on `807729`) continue to be checked
  and all six finished class snapshots remain byte-identical.
- Hostile `SPELL_ATTR5_LIMIT_N` spells can prove their single-target limit directly through
  `kind: "single_target"` without modifying `compare.py`.
