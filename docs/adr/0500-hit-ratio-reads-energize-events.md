# 0500. hit_ratio reads energize events

- Status: accepted
- Date: 2026-11-13

## Context

Bone Legion 707006 and 707881 state "and its Runic Power generated by $s2%" (Effect[1] SPELLMOD_EFFECT2 on Lichfrost's
energize 804112). The claims were parked because `hit_ratio` read damage, healing and swings only, although the harness
already records energizes (`spell_energize_count`, `spell_energize_total`, filtered by caster, spell, target and power).

## Options

1. A new energize-ratio kind: it would repeat the hit_ratio arms, trials, pooling and judge.
2. Add the energize metric pair to `HIT_RATIO_METRICS`. Chosen.

## Decision

- `HIT_RATIO_METRICS['spell_energize_total'] = 'spell_energize_count'`; the reads carry `spell` only (the energize
  lands on the caster, not on the hit target).
- A `critical` filter, `force_crit` or `rate: "critical"` is refused for energizes.

## Consequences

- The Lichfrost energize rolls with DieSides 31, so the 2-point band needs about 2800 energizes per arm at +25% and
  about 800 at +50% (route note). Those counts use the existing pooling (G-20); the entry states its sizing.
- Which spell id the energize event carries (804112 or the Lichfrost rank) is read from a pilot run before the claim
  is judged.
- Templar `generate --class 19`, `--stack` and Necromancer `--class 23` are byte-identical to bf83cf15b1.
- Tests: `HitRatioEnergizeTests` (test_behaviours.py).
